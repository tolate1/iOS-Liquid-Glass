# Completion, learning and handoff

## Preserve useful experience

After a meaningful UI stage, update the knowledge log with the observed issue, causal mechanism, correction, environment, evidence and remaining uncertainty. Retain reusable constraints, including palette, typography, hierarchy, motion, input semantics, overlays, accessibility, rendering source, performance and browser compatibility. Deduplicate; do not append a transcript or collect every CSS value.

Keep implementation facts separate from visible quality and user confirmation. Record incorrect earlier diagnoses as disproved when evidence contradicts them. Treat an acceptance plan as open if its required recording, device, or performance proof is missing, even when code is published.

## Project context

Keep exact release, component map, data/formula boundaries, build commands, source revision, completed work, failed checks and next steps in the application's context file. Do not copy private workouts, account identifiers, credentials or diagnostic sessions into this reusable skill or its public mirror.

## Deliveries for this owner's UI work

1. Complete the authorized change, appropriate checks and supported publication.
2. Save useful new experience in this skill using the personal-skill workflow; validate and verify the saved state.
3. Update an explicitly configured GitHub skill mirror after checking its current tree. Preserve unrelated files and licenses; use a normal update with a concurrency guard. Application-source synchronization requires its own configured destination.
4. Produce a project source ZIP from the intended source revision, including launch instructions, dependency lockfile and current project context. Exclude dependencies, runtime records, caches, credentials, local environment files and Git internals. Verify ZIP integrity and entry list, then save and link the deliverable.
5. Report the live result, source ZIP, skill update and GitHub result separately. Say which acceptance checks remain. Do not imply native iOS optics or hardware performance from desktop evidence.

If a destination or permission is missing, finish the independent work and identify only the missing part. Do not substitute another repository or silently create a public one.
